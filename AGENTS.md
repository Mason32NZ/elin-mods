# Material Alchemy Project Guide

## Project

Material Alchemy is an Elin BepInEx plugin that adds configurable, non-overwriting crafting recipes.

- Plugin GUID: `m32.material_alchemy`
- Plugin name: `Material Alchemy`
- Project file: `MaterialAlchemy/MaterialAlchemy.csproj`
- Plugin source: `MaterialAlchemy/MaterialAlchemyPlugin.cs`
- Workshop package metadata: `MaterialAlchemy/package.xml`
- Workshop thumbnail: `MaterialAlchemy/preview.jpg`
- Workshop description: `MaterialAlchemy/workshop.bbcode`

## Repository Layout

- `README.md` contains the player-facing overview, recipe list, and configuration notes.
- `AGENTS.md` contains contributor and coding agent instructions.
- `MaterialAlchemy/` contains the plugin source and Workshop package files.
- Build output is written to `MaterialAlchemy/dist/MaterialAlchemy/`.

## Build

Build the release package from the repository root with:

```text
dotnet build MaterialAlchemy/MaterialAlchemy.csproj --configuration Release
```

The build copies the DLL, `package.xml`, and `preview.jpg` into `MaterialAlchemy/dist/MaterialAlchemy/`.

## Elin Compatibility

The `<version>` in `package.xml` is the Elin game compatibility version, not the plugin version. Keep it aligned with the installed game version.

The BepInEx plugin version is defined separately in `MaterialAlchemyPlugin.cs`.

## Configuration

Configuration is generated by BepInEx at:

```text
BepInEx/config/m32.material_alchemy.cfg
```

Recipe toggles are independent. All recipes default to enabled except the Material Hammer recipe. The Material Hammer ingot count defaults to 10 and must remain configurable.

## Packaging

The Workshop package must contain:

- `MaterialAlchemy.dll`
- `package.xml`
- `preview.jpg`

Do not include source files, `bin/`, `obj/`, `dist/`, local configuration files, or development scripts in the Workshop package.

Keep the package ID `m32.material_alchemy` unchanged after publishing.

## Change Guidelines

- Do not overwrite vanilla recipe definitions.
- Preserve input materials on every conversion.
- Keep recipe configuration keys stable after release.
- Build with zero warnings and errors before deployment.
- Test save loading and all affected crafting stations after changing Harmony patches.
